# Architecture Grill profile

## 目标与产品意图门

在 approved PRD 基础上澄清系统边界、质量属性、关键契约和高成本技术决定。

PRD 若缺少会改变系统边界、数据含义、权限模型或核心流程的产品决定，列出明确缺口并交回 PRD，不用架构假设遮盖。

## 事实来源

按通用本地事实优先规则，重点读取：

- approved PRD、关联 research-note、已有 Arch 与 ADR
- 实际代码、依赖、API、数据模型、部署和运行配置
- `framework.json.project.languages` 等项目事实
- tech-eval 基于官方来源核实的技术版本与生命周期

brownfield 约束以实际代码和配置为准；用户意图仍以 approved PRD 为准。

## 决策树

1. 系统边界、用户和外部系统
2. 外部消费边界和 external oracles
3. 性能、安全、可靠性、一致性、合规等质量属性预算
4. 团队、运行环境、部署和维护约束
5. 架构风格与主要分层
6. 数据所有权、生命周期和一致性模型
7. 模块职责和依赖方向
8. API、错误、重试、幂等和降级契约
9. 认证、授权、密钥和配置边界
10. 可观测性、迁移、部署和恢复
11. 目录与开发约定

## 推荐依据

- PRD、非功能需求和现有系统事实
- 可逆性、复杂度、维护成本和故障面
- 官方技术证据
- 至少两个真实可行方案的比较

## ADR 与产物归属

仅当决定同时满足以下条件时标为 `ADR-NNN` 候选：

- 难以逆转，改变成本有实质影响
- 缺少上下文时未来维护者会觉得意外
- 存在真实替代方案和实质权衡

普通、局部、可逆决定只进入 Arch 所属章节。ADR 归 Arch 权威范围，不创建独立正式 doc_type；Arch-lite 不创建 ADR。调研和备选保留在该阶段单份 research-note。
