# PRD Grill profile

## 目标与边界

澄清 What、Why、Who、范围、成功定义和可验证需求，不讨论实现方案。

- 代码只用于核实现状，不得用现有实现替代产品意图
- 不用框架、数据库、缓存或服务划分等实现偏好回答产品问题
- 目标与范围未确认前，不逐条细化 AC

## 事实来源

按通用本地事实优先规则，重点读取：

- 用户原始需求、已有产品说明和当前会话选择
- 现有 PRD、research-note、反馈与变更请求
- brownfield 项目的当前可见行为
- 当前执行模式、业务约束和已记录领域术语

## 决策树

1. 背景、用户问题和预期结果
2. 目标用户、使用场景和关键任务
3. 首版范围与明确非范围
4. 核心用户行为、业务规则和边界场景
5. 成功指标和验证方式
6. 非功能需求
7. P0/P1/P2 和依赖
8. 约束、假设和领域术语

## 推荐依据

- 用户价值和是否形成最小可用闭环
- 可验证性与范围控制
- 下游 Arch、UI 和 DEV-PLAN 所需信息

## 产物归属

- 终态决定进入 PRD 对应章节
- 假设进入 PRD 约束与假设位置并标 `[ASSUMPTION]`
- 业务术语进入 PRD Glossary/术语表；沿用现有 `GL-NNN` 实体约定，不创建独立 glossary
- 调研、备选和被否决方案保留在该阶段单份 research-note
- PRD 不创建 ADR
