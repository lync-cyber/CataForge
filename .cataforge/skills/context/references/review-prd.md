# PRD 实质审查 profile

Layer 2 审查 `prd` 时按 review.md 路由加载本文件。审查立场: 假设设计存在缺陷并求证——每个维度回答「若按本文档直接开发,哪里会返工或做错」,而非确认章节齐全。

## 实质维度

**问题定义与价值 (completeness)**
- 目标用户、待解决问题、不解决的后果三者可从文档重建;成功指标可证伪(数值或可观测行为)
- 差: 「提升团队协作效率」——无法证伪;好: 「审批流转时长中位数从 2 天降到 4 小时内」

**范围与最小闭环 (completeness)**
- P0 集合独立构成可用闭环: 只交付 P0 时用户能完成核心任务;显式非范围存在且与功能列表无矛盾
- 差: P0 含「数据导出」却无任何产生数据的功能;好: P0 链路「录入→处理→查看」自闭环,导出降 P1

**AC 可验证性与失败路径 (ambiguity)**
- 每条 AC 的 Then 是可观测断言;每个 P0 功能除 happy path 外定义至少一条失败/边界行为(非法输入、越权、依赖不可用时用户看到什么)
- 差: 「AC: 登录功能正常」;好: 「Given 密码连续错误 5 次, When 再次提交, Then 显示锁定提示且 15 分钟内拒绝登录」

**优先级分布 (feasibility)**
- P0 语义是「没有则产品不可用」;P0 占比超过约 40% 或功能全标 P0 时,逐项索要「缺它为何不可用」的依据,给不出即判优先级未真实评估

**业务规则完备性 (completeness)**
- 权限模型(角色×操作)、状态流转(合法与禁止转换)、并发/重复操作语义(同一资源被同时修改)在涉及处有定义
- 差: 「管理员可以管理用户」;好: 枚举角色×操作矩阵及越权时的拒绝行为

**非功能需求真实性 (feasibility)**
- NFR 数值有出处(用户规模推算、上游约束、法规),无依据的标 `[ASSUMPTION]` 而非伪精确
- 差: 照抄「响应 <200ms、可用性 99.99%」;好: 「50 人内部工具,页面可交互 <2s,无高可用要求」

**内部一致性 (consistency)**
- 同一概念全文单一术语;功能间无隐性矛盾(某功能假设的数据/角色在另一处不存在);用户旅程引用的功能全部真实在列

## 严重度锚点

| 缺陷 | 起评 |
|------|------|
| P0 集合不构成可用闭环、核心概念跨章节矛盾 | CRITICAL |
| P0 功能无失败路径定义、AC 不可验证 | HIGH |
| 优先级未真实评估(P0 膨胀无依据) | HIGH |
| 成功指标不可证伪、NFR 伪精确 | MEDIUM(P0 相关升 HIGH) |
