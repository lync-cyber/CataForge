# UI-SPEC 实质审查 profile

Layer 2 审查 `ui-spec` 时按 review.md 路由加载本文件。审查立场: 假设设计存在缺陷并求证——每个维度回答「按此规格实现,用户在哪条路径卡住、哪个状态没有着落」,而非确认章节齐全。

## 实质维度

**任务流完整性 (completeness)**
- PRD 每个 P0 功能有页面/流程承载,从入口到完成状态闭环(含返回/取消路径);无「进得去出不来」的死端页面

**状态覆盖 (completeness)**
- 每个数据承载页面定义 loading / empty / populated / error 状态;涉权限页面定义权限不足表现;网络型产品定义离线/弱网表现
- 差: 只画 populated 理想态;好: 空态给出引导动作,错误态给出恢复动作

**信息架构与导航一致性 (consistency)**
- 导航模型全站单一;同层级页面结构模式一致;用户当前位置可感知;深层页面有返回路径

**设计方向兑现 (consistency)**
- §0 设计方向的调性关键词在色彩/排版/空间构成(密度/留白/层级节奏)/组件规格中可指认兑现;无「方向说克制、组件规格五彩斑斓」式断裂

**设计系统自洽 (consistency)**
- 定义的 token 有消费方、组件引用的 token 有定义(死 token / 幽灵引用即缺陷);组件变体间有可辨识视觉差异;同语义跨页面同表现
- 保真类 AC 按 `.cataforge/references/fidelity-ac.md`: 锚定渲染/计算后效果,不锚定源码字面

**可访问性实质 (completeness)**
- 文本/背景对比度给出数值或指认达标 token 对;交互密集页面定义键盘可达与焦点顺序;状态区分不独依赖色彩
- 差: 「遵循无障碍规范」一句话;好: 正文对比度 ≥4.5:1 并指认 token 对,表单错误除颜色外有图标与文案

**响应式关键屏 (completeness)**
- 声明支持的断点范围;核心任务流在最小断点可完成;极端内容(长词、大数、空列表)的伸缩行为有定义

**与 PRD/ARCH 边界一致 (consistency)**
- 页面引用的功能、数据、权限在 PRD/ARCH 真实存在;交互隐含的系统能力(实时刷新、模糊搜索)有 ARCH 支撑;不以视觉设计掩盖上游缺口

## 严重度锚点

| 缺陷 | 起评 |
|------|------|
| P0 功能无页面/流程承载、任务流断链 | CRITICAL |
| 数据页面缺 error/empty 状态定义 | HIGH |
| 交互隐含能力无 ARCH 支撑 | HIGH |
| 对比度/键盘可达未定义(交互密集产品) | HIGH |
| 死 token / 幽灵引用、同语义跨页面不同表现 | MEDIUM(核心 token 升 HIGH) |
