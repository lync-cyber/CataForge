# 测试套件性能纪律

测试套件随项目增长，执行时长直接决定开发反馈循环；规划与编写测试时按以下四条保持套件可持续。语言具体语法见 testing skill `references/lang-<lang>.md`。

## 1. 慢测标签分层

- 慢测（构建产物 / 启动容器或服务 / 外部进程 / 网络 / 大数据集 / 显式等待）必须打分类标签——marker / tag / 目录约定三选一，随项目测试执行口径一次性声明
- 判定：新测试引入子进程、网络客户端、真实服务、休眠或轮询超时，即属慢测候选
- 标签缺失会让全量跑成为唯一选项，套件越大内循环越不可用

## 2. 昂贵确定 setup 跨用例复用

- 构建一次即确定的环境（已构建产物、已初始化的数据存储、预置 fixture 数据）用 suite 级共享 fixture 构建一次复用，不每测重建
- 判据：setup 产物在用例间只读或可低成本重置 → 升共享；会被用例改写且重置成本高 → 保持 per-test 隔离
- 每测各自重建昂贵 setup 是套件随测试数线性变慢的首要根因

## 3. 进程内优先

- 可进程内验证的逻辑不 spawn 子进程 / 起服务；子进程仅用于验证真实安装、CLI 入口、跨进程边界，且必须随之打慢测标签

## 4. 并行就绪

- 测试相互隔离：不共享可变全局、不依赖执行顺序、不独占固定端口 / 路径等排他资源，使 runner 支持并行时可直接按核数并行
